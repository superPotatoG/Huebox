## 1. 管理原则（来自参考文章，按单人项目精简）

1. **里程碑是“能玩、能给别人看”的东西，不是功能列表。** 每个里程碑都要有一个陌生人能玩完的版本。
2. **阶段门（phase gate）**：达不到上一个里程碑的“完成标准”，就不进入下一阶段。
3. **顺序固定**：核心循环 → 垂直切片 → 内容铺开 → 打磨。不跳步。
4. **时间不够时砍范围，不砍质量、不推迟截止日期。** 砍的顺序见第 3 节的 Won't / Could。
5. **缓冲放在集成点，不放在每个任务里**：总时间留出约 15–20%。本计划的缓冲在第 7 周（感恩节）和第 9 周。
6. **功能冻结（Feature Freeze）**：11-15 之后不加任何新机制（GDD 的 scope gate）。
7. **每周固定 15 分钟复盘**（周日）：完成了什么、卡在哪、下周前 3 件事是什么、里程碑把握度是否下降。
8. **尽早、经常做测试**：每个里程碑至少找 1 个没看过设计的人玩，只观察，不指导。
9. **记录决策，不只记录成果**：每个偏离 GDD 的决定都写进决策日志，并写清楚原因。
10. **重要任务用三点估算**（乐观 / 最可能 / 悲观）；排期按“最可能”，悲观值用来判断风险。

## 2. 每周节奏

| 时间 | 做什么 |
|---|---|
| 周一 | 从 CHECKLIST 选出本周前 3 件事，写进周复盘的“下周计划” |
| 工作日 | 每次开工前花 2 分钟写下“今天做什么 / 卡在哪” |
| 周五或周六 | 跑一遍完整测试：自动化测试 + `-HueSelfTest` + 自己从头玩一遍 |
| 周日 | 15 分钟复盘：勾选 CHECKLIST，更新风险和决策日志，如需要就砍范围 |

建议投入：**每周 8–10 小时**（GDD 原估 5–7 h/周，但现在剩下的工作量更大）。

## 3. 功能优先级矩阵（MoSCoW）

| 优先级 | 内容 |
|---|---|
| **Must**（不做就不能交） | Level 1 四个练习 ✅（第 4 关：颜色钥匙）；**双视角**（俯视摆放 + 侧面跟随 + 小地图）；剪影舞者皮肤 ✅；Level 2 展览箱（8×8，4 个 B 源，按顺序完成目标：出发 → 远端 → 返回 → 停在中央；用上砖 + 加色混合器 + 黄色聚光灯里的黄色动作）；主菜单 / 关卡选择 / 暂停菜单（Resume / Restart / Quit）；开场委托画面；完成提示 + 结束音效；打包好的 Windows 独立版本；控制说明；GDD PDF |
| **Should**（应该做） | **沙盒模式**（自由视角、道具不限量、可选皮肤，不存档）；UMG 版 HUD（替换 Canvas）；简单材质（木头 / 纸 / 金属）；6–8 个音效；设置（音量、灵敏度、画质 Low/Medium）；3–5 人测试并完成迭代；Unreal Insights 性能记录 |
| **Could**（有时间再做） | **舞台屏风**（彩色纸屏挡在轨道上，舞者靠近时收到同色光就打碎；Level 2 灰盒跑通后再做，来不及就只放进沙盒）；每个皮肤、每种钥匙颜色各自的动作（舞步、武术、剑术；现在一个皮肤只有一个动作）；背景音乐；Niagara 脉冲特效；脉冲拖尾；更漂亮的模块模型；轨迹回放线 |
| **Won't**（本学期不做，GDD 已排除） | 传送门；砖和舞台屏风以外的机关类型（色门、色开关、双色锁、灯笼目标、滤光片、棱镜：功能冻结前不做，以后可以放进沙盒）；角色动画；自由搭建存档；最少模块 / 最快时间评分；手柄 / VR |

**砍范围的顺序**（照抄 GDD）：音乐 → 装饰 → 复杂特效 → 简化 Level 2 的布线（两关和颜色 / 时序核心必须保留）。

## 4. 风险登记（ROAM：Resolved 已解决 / Owned 负责跟踪 / Accepted 接受 / Mitigated 已缓解）

| # | 风险 | 可能性 | 影响 | 状态 | 应对 |
|---|---|---|---|---|---|
| R1 | **项目没有版本控制**，误改或硬盘问题会丢掉全部进度 | 中 | 极高 | Owned | 第 1 周：`git init` + UE `.gitignore` + 推到私有远程仓库（`.uasset/.umap` 用 Git LFS）。之后每次能跑的状态都提交一次 |
| R2 | Level 2 的四路时序难以调到“可解但不靠运气” | 中 | 高 | Owned | 先做灰盒并跑 `-HueSelfTest` 验证基准解；只调一个参数，每次调完重跑 |
| R3 | 不同帧率下物理结果不一致 | 低 | 高 | Mitigated | 已在 30/60/120 FPS 下验证 Level 1；Level 2 也必须做同样的验证 |
| R4 | 打包版本缺资源或崩溃（编辑器里正常） | 中 | 高 | Owned | 第 4 周就做第一次打包，之后每个里程碑都打包一次，不要拖到最后 |
| R5 | 期末周 / 其他课程挤占时间 | 高 | 中 | Accepted | 第 9 周只留验证和提交；第 7 周（感恩节）是缓冲 |
| R6 | 测试玩家看不懂颜色或时序规则 | 中 | 中 | Owned | 第 2 周和第 6 周各做一次测试；HUD 和提示文字按观察结果改 |
| R7 | 美术 / 音效拖慢进度 | 中 | 中 | Mitigated | 美术排在功能冻结之后，且限 6 种基础材质；用 Could 列表兜底 |
| R8 | UE 5.8 / VS 2026 工具链问题 | 低 | 中 | Accepted | 不中途升级引擎（GDD 要求） |
| R9 | 表演物（小车）玩起来不吸引人 | 已发生 | 高 | Mitigated | 换成剪影舞者加舞伴；表演区挪到棋盘正后方；停止区改成聚光灯。等测试 #1 验证 |
| R10 | 双视角系统工作量最大，可能挤占 Level 2 | 中 | 高 | Owned | 第 3 周集中做；功能冻结前没做完就砍小地图，改用 Tab 切换 |

## 5. 决策日志

| 日期 | 决定 | 原因 |
|---|---|---|
| 10-08 | 玩家改为第一人称 WASD 行走 + 鼠标左键交互（GDD 原为环绕工作台的相机） | 你的要求；仍然没有可见身体，符合 GDD 第 5 节 |
| 10-08 | 转向块改为双向直角（两个相邻面都是端口） | 只用 Q/E 旋转就能做出左转和右转，少一个按键 |
| 10-08 | 原型阶段用 Canvas HUD | 不需要任何资产；UMG 版排在第 4–5 周 |
| 10-08 | 新放置的延迟块默认 0 s | 否则第 3 关放下就直接通过，学不到调时间 |
| 10-08 | 通关后小车不冻结，继续完成运动 | GDD：完成的装置自己完成表演 |
| 10-08 | 走到另一块棋盘时，自动释放已结束的那一关 | 否则一关完成后会锁死其他关的编辑 |
| 10-08 | Space 用于运行，不设跳跃 | GDD 规定 Space 控制运行 |
| 10-20 | 表演物换皮：官方外观用**剪影舞者**，A 锚点改成舞伴；做成数据驱动的皮肤系统（Project Settings 里管理列表） | 小车在实际游玩中体验不好；舞伴让“同色相斥、异色相吸”有了含义；皮肤系统让沙盒模式可以自定义外观 |
| 10-20 | 表演区挪到棋盘正后方，停止区改成纸屏上的聚光灯 | 搭线和观看在同一个视野里；目标从一个百分比变成看得见的东西 |
| 10-20 | 教学关采用**双视角**：俯视摆放（锁定在格子上方）→ 按 Space 切到侧面跟随视角，并在角落显示格子小地图 | 现在的自由视角太自由；回到 GDD 原本的工作台设计；小地图保证运行时还能看到脉冲 |
| 10-20 | 自由第一人称视角保留为**沙盒模式**（主菜单进入）：道具不限量，可选皮肤，不做存档 | 把自由视角变成玩点；GDD 已把存档列为不做 |
| 10-20 | 教学关的道具改由托盘 UI 提供，地上拾取只留给沙盒 | 俯视视角下从地上捡东西不合理 |
| 10-20 | Level 2 灰盒顺延到第 4 周；M2 改为“双视角 + 换皮教程” | 双视角是体验的基础，先做 |
| 10-21 | 双视角已实现：`AHueBuilderPawn`（俯视 + 光标）、`AHueStageCamera`（侧面跟随）、HUD 小地图；放置规则抽成 `UHueBuildToolComponent`，俯视和沙盒共用；教学模式为默认，`-HueSandbox` 进入第一人称 | 避免两套放置逻辑；沙盒模式以后只需要加菜单入口 |
| 10-21 | 模块改为 2D 白色平板，固定单元（光源 / 接收器 / 障碍）保留颜色；沙盒的地上拾取物仍用按类型区分的颜色 | 俯视下清楚，侧面镜头也不会被方块挡住 |
| 10-22 | **颜色是钥匙，方块是锁**：颜色本身没有效果，效果由它碰到的东西决定。动作（舞步 / 武术 / 剑术）只是皮肤层面的表现，不需要玩家记“颜色 → 动作” | 玩家从场景里的锁倒推需要什么颜色，天然支持多种解法；和皮肤系统的思路一致 |
| 10-22 | 颜色改为**加色光（RGB）**：A = 红、B = 青、N = 白，新增 G 绿 / Y 黄 / M 品红 / V 紫。混合器 = 没有共同原色的两种光相加（A + B = N 不变，A + G = Y）；变色块 = 互补色（A ↔ B 不变）；只有 A / B / N 改变舞者的运动 | Level 1 的规则和解法完全不变；A 从琥珀色改成红色，否则会和黄色分不清 |
| 10-22 | 新增**砖**（固定块）：**任何光**都能打碎，打碎它的那束光会被用掉；同一时刻到达的其他光也一起被用掉 | 你试玩后的修正：“可以用任何光开路”，颜色留给舞台上的动作 |
| 10-22 | **黄光的作用在舞台上**：钥匙颜色（Y 等）到达舞者时，她当场做这个颜色的动作，运动本身不受影响；目标是“在黄色聚光灯里做黄色动作”，她是跑着经过聚光灯的，所以要卡时机。动作动画来自皮肤（剪影舞者暂用模板的出拳 MM_Attack_01） | 你试玩后的修正：“应该是跑过去，然后在聚光灯下做黄的动作”；聚光灯本身是黄色 |
| 10-22 | 教程第 4 关 **Colour Key** 改为三步：转向把备用的 B 引去打开砖 → A + G 混出 Y → 延迟 Y，让它在舞者跑过 52–68% 的黄色聚光灯时到达（延迟 2.25 s 或 2.5 s） | 新概念先有一关只教它，Level 2 才能直接用；三步分别复用练习 1、3 和延迟 |

> 功能冻结前要把这些决定同步写进 GDD（v2.1）。
